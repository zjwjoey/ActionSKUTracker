# Action 西班牙站正式导出 Profile：Template 1

> 实施顺序：Template 1 是第二阶段详细 Profile。必须先完成并验收 ES/ZH 两个独立
> 无图基础导出；基础版本未达到 `docs/EXPORT_IMPLEMENTATION_PLAN.md` 的完成标准前，
> 不开始历史矩阵、三表合一和图片嵌入。

## 1. Profile 身份

| 项目 | 固定值 |
| --- | --- |
| `template_id` | `action_full_template_1` |
| `template_version` | `1` |
| 输出格式 | `.xlsx` + 同名 `.manifest.json` |
| 建议文件名 | `YYYYMMDDAction商品全量_三表版.xlsx` |
| 工作表数量 | 3 |
| 数据来源 | 同一日期、同一正式 `run_id` |

该 Profile 是第二阶段目标导出契约。现有程序的两个独立 ES/ZH 无图文件是第一阶段
基础版本；它们需要先达到可日常使用状态，后续 Template 1 必须复用其正式来源、
字段构建和对账能力，不能视为一次性代码，也不能视为 Template 1 已完成。

## 2. 正式来源

当日导出只接受已经正式提交的来源：

- `qa_report.json.passed = true`；
- `run_report.json` 为 `FULL_COMMIT`；
- Master `05_RUN_LOG` 对应 run 为成功；
- 请求日期与来源业务日期一致。

当日有效 SKU 集合取正式 Listing/CURRENT Presence。Sitemap 是覆盖与发现证据，不是直接的在售清单；Sitemap-only、无效 URL、无法确认的 SKU 不得因为出现在 Sitemap 中就写为当日在售。

找不到唯一正式来源时导出必须失败，不得回退到最近日期、dry-run 或 QA FAIL 数据。

## 3. 工作表一：商品上下架明细

### 3.1 用途

参考 `Action商品上下架明细 26.08.24.xlsx` 的结构维护长期 SKU Presence 矩阵。

它是一张历史 union 表：历史出现过或当日首次出现的 SKU 均保留，一 SKU 一行。它不是“只含当日在售 SKU”的 CURRENT 表。

### 3.2 固定基础字段

前五列固定为：

| 顺序 | 表头 | 类型 | 来源与规则 |
| ---: | --- | --- | --- |
| 1 | 序号 | Number | 稳定排序后从 1 开始连续编号 |
| 2 | 编号 | Text | SKU；唯一、非空，保留前导零 |
| 3 | 中文品名 | Text | 当前有效字典结果；未知时保留西语 fallback 并标记审核，不删除 SKU |
| 4 | 图片链接 | URL / null | 最新有效官网图片链接 |
| 5 | 商品链接 | URL | 最新有效 Action ES 商品链接 |

基础字段之后是按业务日期升序排列的 Presence 列。

### 3.3 日期列

- 每次导出在最右侧增加当前 `export_date` 对应的日期列；
- 表头显示格式固定为 `yy.mm.dd`，例如 `26.08.26`；
- 表头是日期标签，标准业务日期同时以 `YYYY-MM-DD` 写入 manifest；
- 同一日期重复导出时必须更新原日期列，不得生成重复列；
- 单元格只能是数值 `1` 或数值 `0`：
  - `1`：该 SKU 属于该日期正式有效在售集合；
  - `0`：该 SKU 不属于该日期正式有效在售集合；
- 不允许用空白、`Y/N`、布尔值或 Sitemap Presence 替代 0/1。

### 3.4 当日新品

如果当日有效 SKU 在历史 union 中不存在：

1. 将该 SKU 追加到 union；
2. 填写已提取到的商品链接、图片链接及中文品名；
3. 以前所有日期列写 `0`；
4. 当前日期列写 `1`；
5. 中文品名尚未完成时仍保留该 SKU，并进入字典 Review Queue；
6. 新品详情或图片缺失不得阻止 Presence 写入。

现有 SKU 的基础展示字段可以使用最新确认字典值更新，但过去日期的 0/1 事实永远不得由字典或生命周期日期反推、改写。

### 3.5 强制核对

设当日正式有效 SKU 集合为 `CURRENT_VALID`：

```text
SUM(当日日期列) == COUNT(DISTINCT CURRENT_VALID.sku)
当日日期列为 1 的 SKU 集合 == CURRENT_VALID SKU 集合
```

例如 2026-08-26 有 5,476 个有效 SKU 时，`26.08.26` 列必须恰好有 5,476 个 `1`。这个数量不以 Sitemap 原始 SKU 数为准。

## 4. 工作表二：今日西班牙语清单

### 4.1 范围

只包含当日 `CURRENT_VALID` SKU，一 SKU 一行，不嵌入图片。

工作表名称固定为 `今日西班牙语清单`。

### 4.2 固定 14 列

| 顺序 | 表头 | 类型 | 规则 |
| ---: | --- | --- | --- |
| 1 | 图片 | 空白 | 始终空白，不插图 |
| 2 | 编号 | Text | SKU |
| 3 | 标题 | Text | 官网西语名称 |
| 4 | 分类1 | Text | 官网西语一级分类 |
| 5 | 分类2 | Text | 官网西语二级分类 |
| 6 | 规格 | Text | 官网西语规格 |
| 7 | 折后价 | Number / EUR | 官网当前售价；列名仅为模板兼容，不单独证明促销 |
| 8 | 原价 | Number / EUR / null | 仅在有效原价严格大于当前售价时显示 |
| 9 | 单价 | Text / null | 官网西语单价 |
| 10 | 描述 | Text / null | 官网西语描述 |
| 11 | 产品详情 | Text / null | 官网西语产品详情 |
| 12 | 图片链接 | URL / null | 官网图片 URL |
| 13 | 商品链接 | URL | Action ES 商品 URL |
| 14 | 备注 | Text / null | 官网西语标签和稳定状态说明 |

西语工作表不得被中文商品字典反向覆盖。品牌专名本身不是中文污染。

## 5. 工作表三：今日中文清单

### 5.1 范围

只包含当日 `CURRENT_VALID` SKU，SKU 集合和排序必须与 `今日西班牙语清单` 完全相同。

工作表名称固定为 `今日中文清单`。

### 5.2 固定 14 列

列头与西语表完全相同：

```text
图片、编号、标题、分类1、分类2、规格、折后价、原价、单价、描述、产品详情、图片链接、商品链接、备注
```

字段规则：

| 字段 | 规则 |
| --- | --- |
| 图片 | 嵌入已存在的本地 250×250 白底图片 |
| 编号 | 与西语表相同 |
| 标题 | 中文标准品名，品牌按正式品牌字典保留 |
| 分类1 | 15 个固定中文一级类目之一 |
| 分类2 | 字典确认的中文二级类目 |
| 规格 | 中文标准化规格 |
| 折后价、原价 | 与西语表数值完全一致 |
| 单价 | 中文单位标准化，数值不变 |
| 描述 | 中文描述 |
| 产品详情 | 中文产品详情 |
| 图片链接、商品链接 | 与西语表完全一致，URL 不翻译 |
| 备注 | 中文官网标签、状态、fallback 或图片缺失标记 |

#### 品牌名与中文品名统一规则（2026-08-28）

- 已确认品牌且品牌确实是商品名称组成部分时，中文品名统一使用“`品牌标准名`牌`商品通用名`”格式，例如 `Stanger牌记号笔`、`Lunetta牌糕点饼干`。
- 品牌标准名保留官方/字典写法（大小写、数字和型号不翻译），只在品牌与商品通用名之间增加一次“牌”；不得写成“牌牌”，也不得重复品牌。
- 品牌仅作为系列、型号或包装文字，且中文品名中已自然包含该专名时，可保留专名但不重复追加“牌”；该例外必须有字典或人工证据。
- 未确认、未知或无法从西语事实可靠识别的品牌，不得从标题臆测；品名保留通用名并进入 `BRAND_CANDIDATE`/`NAME_REVIEW`。
- 西语事实字段（西语品名、规格、描述、详情）绝不套用“牌”规则；该规则只作用于中文品名展示字段。
- 旧中文值也必须按同一规则复核；`MODEL_TRANSLATED` 不能绕过品牌格式检查，未通过者标记 `NEEDS_REVIEW`。

### 5.3 中文解析优先级

逐 SKU、逐字段使用：

1. 同 SKU、同字段人工覆盖；
2. 商品字典已确认且 `source_hash` 有效的值；
3. 品牌、类目、术语正式字典；
4. `source_hash` 与当前西语事实一致的有效模型结果；
5. 西语 fallback，并在备注写精确的 `中文字段待审核`。

中文缺失不能删除 SKU，也不能让 ES/ZH 两张表的 SKU 集合不同。

### 5.4 图片规则

- 只在 `今日中文清单` 第一列插图；
- `今日西班牙语清单` 的图片列保持空白；
- Export 只读取本地已存在图片，不联网下载；
- 图片必须为 250×250 像素、白色背景，不拉伸、不裁掉主体；
- 图片按 SKU 确定性匹配，禁止仅按商品标题模糊匹配；
- 本地图片缺失时图片单元格留空，备注增加 `图片缺失`，SKU 仍保留；
- manifest 记录成功插图数、缺图数和异常图片数。

## 6. 三张表的共同排序和格式

- SKU 按数值升序稳定排序；非纯数字 SKU 再按文本升序；
- 第一行启用筛选并冻结；
- SKU 写为文本；价格写真正数值，使用 EUR 数字格式；
- 链接保留真实 URL 和可点击超链接；
- 描述、产品详情自动换行并顶端对齐；
- 第一张表日期列使用数值 0/1，并对当前导出日期列使用与历史列一致的样式；
- 中文图片行按 250×250 图片合理设置行高和列宽；
- 西语表不因保留空图片列而设置 250×250 大行高；
- 三张表不得增加临时说明列；机器可读说明写入旁路 manifest。

## 7. 跨表一致性校验

导出成功必须同时满足：

1. 三张表 SKU 均非空且各自唯一；
2. 第一张表当日为 `1` 的 SKU 集合等于当日正式有效 SKU 集合；
3. ES 与 ZH 的 SKU 数、SKU 集合和排序完全相同；
4. ES 与 ZH 的价格、图片链接、商品链接逐 SKU 完全相同；
5. ES/ZH 的 SKU 数等于第一张表当日 `1` 的合计；
6. 当日新品全部出现在第一张表，过去日期为 0、当日为 1；
7. Sitemap-only SKU 不得作为当日有效 SKU 写入；
8. 中文缺失和图片缺失均已标记，但没有造成 SKU 丢失；
9. 工作表名称、数量、14 列表头和顺序完全符合本 Profile；
10. 导出过程没有修改任何来源文件。

任一校验失败时保留诊断和预览，不发布正式工作簿。

## 8. Manifest

旁路 manifest 至少包含：

```json
{
  "template_id": "action_full_template_1",
  "template_version": 1,
  "export_date": "2026-08-26",
  "run_id": "<formal_run_id>",
  "source_kind": "MASTER_CURRENT | FORMAL_SNAPSHOT",
  "source_hash": "<sha256>",
  "history_union_sku_count": 0,
  "current_valid_sku_count": 5476,
  "new_sku_count": 0,
  "presence_one_count": 5476,
  "es_sku_count": 5476,
  "zh_sku_count": 5476,
  "es_zh_sku_set_equal": true,
  "zh_image_embedded_count": 0,
  "zh_image_missing_count": 0,
  "generated_at": "<ISO-8601>"
}
```

示例中的 5,476 只说明数量校验方式，不是永久业务基线；每次导出必须读取对应日期的正式有效 SKU 数。

## 9. 幂等与版本规则

- 相同 `export_date + run_id + template_version` 重复导出，三张表的数据、顺序和来源哈希必须一致；
- 相同导出日期不得重复追加日期列；
- 修改工作表数量、名称、列头、列顺序、0/1 语义或图片规则时必须提升模板版本；
- 不允许为迁就一次异常数据临时改变 Template 1。

## 10. 实现验收测试

后续实现至少补充：

1. 三张工作表名称和数量测试；
2. 第一张表追加当日日期列测试；
3. 同日重复导出不重复列测试；
4. 新 SKU 加入 union、历史为 0、当日为 1 测试；
5. `SUM(当日列) == CURRENT_VALID SKU 数` 测试；
6. Sitemap-only SKU 排除测试；
7. ES/ZH SKU 集合、顺序、价格和链接一致测试；
8. 中文字段级优先级和 fallback 测试；
9. 仅中文表插图测试；
10. 图片缺失不删除 SKU 测试；
11. QA FAIL / dry-run 禁止正式导出测试；
12. 导出前后来源文件哈希不变测试。

这些测试在 GitHub Actions 中只使用临时 fixture；真实正式来源、图片缓存和视觉检查仍由 Windows 本地发布流程完成。CI 通过不等于 Template 1 已正式发布。
