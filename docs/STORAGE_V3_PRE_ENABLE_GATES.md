# Storage V3 生产启用前门禁

代码合并、独立备份工具启用、完整生产 checkout 升级和历史文件处置分别验收。
合并代码不会注册任务、改变 active.json 或授权业务数据上传。

## 代码身份和运行入口

- 核对审计提交、完整测试、Windows/Ubuntu CI 和干净的候选 checkout。
- 正常 checkout 同时核对分支和提交。detached HEAD 只有明确提供且解析到
  当前提交的 `--expected-ref` 才能替代分支判断；相同的 `--expected-head`
  不能单独绕过分支门禁，空分支名也不能自动通过。
- src 布局的任务必须使用经过验证的安装或以 `<checkout>/src` 为工作目录。
  不依赖交互 PowerShell 中临时设置的 PYTHONPATH。
- 独立 Storage CLI 可以保留原 daily-run checkout。必须配置实际数据根、
  生产保护根和同一个 `daily-run.lock` 目录；不能猜测锁路径。
- 切换整个生产 checkout 前，另行审查生产本地改动和接口迁移。
  文件名相同或候选测试通过不等于所有旧运行行为已经等价验证。

## 备份启用

选择正式仓库、备份范围、责任人、保留政策、容量和运行预算，并核对独立恢复。
仓库密码独立保管；当前用户 DPAPI 记录不能替代另一账号或机器的密码恢复方案。
无人值守凭证保管、STS 续期和失败告警需要明确的运行责任。

云端先完成新后端在专用前缀的人工文件上传、重连和恢复校验；旧 PoC 不能替代。
真实业务首次上传仍需绑定具体范围的授权。生产调度另需配置摘要和恢复证明绑定的
启用记录。生成禁用 XML 不是注册任务，也不是已获启用批准。

## 清理启用

归档或 Kopia 恢复成功不能代替任务终态、Resume 退役、引用闭包、保留期限和
独立回滚职责释放。具体隔离计划、观察后删除计划各自取得独立审批。
默认关闭执行，UNKNOWN 不转成可清理；保留预览不执行仓库危险维护。
